## 5. deepseek_read.py: does it drop or down-rank?
No. Evidence:
- `caps = [(w, t) for w, t in captures_for(day) if w != "deepseek"]` followed by `corpus = "\n\n".join(...)` passes every other writer's full text to the model with no truncation, no sampling, no scoring code.
- The prompt, verbatim: "Keep every item labelled observed / claim / theory and keep its source URL and money tag from the capture you took it from. Do not drop an item because it is unofficial or speculative; label it."
- Output is written as the model returns it, with no post-filter. `temperature: 0.2`.
- Results: no item lost, no label changed in four days (script above). Rule 2 in SYSTEM.md ("Nothing deleted on the way downstream") is met.
Weak points that are not drops:
- It is an LLM paraphrase of a merge, not a deterministic merge, so a drop is *possible* any day; today there is none. Nothing checks it.
- It adds noise: converts "nothing new" into `[claim]` items; carries the same item twice when codex and claude both have it.
- Its Convergence / Divergence / hemisphere sections are never read by the writer.
- It only reads the day's captures present at 09:00 (claude and codex); msi lands in the evening, jaron-x at 21:00 next day, so those are never in the reader's corpus.
- It prompts DeepSeek to be the reader, yet `captures_for` skips only `collectors, brief, market-feed`; any folder with today's file (e.g. a future grok capture) would be merged without a count check.

**The filter that decides what reaches the audience is the news writer**, WRITER.md: "One segment per story worth telling. A thin day is 5-7 segments; a big day 12-18." There is no coverage rule, no "not aired" list, and no check that compares the episode to the captures. Also WRITER.md drops `[theory]` items by design and says the show is "National and world audience", which is fine.

## 6. Recommended fixes (concrete)
1. **Coverage rule in WRITER.md:** every `[observed]` item that has an official or press URL and is not a duplicate must appear in the show, either as its own segment or as a line inside a grouped segment ("Also today"). `[claim]` items above a size bar (war, president, AI frontier model, outage, market-wide) appear too, said as claims. Pure carry-forwards ("carried from 10-03") and "nothing new" lines are excluded.
2. **Add a "Not aired" file written by the writer** (`news/episodes/DAY.skipped.json`: item, source, one-line reason). Jaron or an auditor can see drops at once. This is "DeepSeek can flag but never delete" applied to the last step: the writer may defer, never discard silently.
3. **Add a coverage checker** to `check-episode.mjs` or a small `coverage_check.py`: extract every `[observed|claim]` URL from codex/claude/deepseek for the day and warn when fewer than ~60% appear in the episode sources/ticker, listing the unused ones. Make the Codex backup writer run it too.
4. **Fix the Claude capture or stop counting on it.** Four WebSearch summaries per domain returned stale pages on 10-06 and 10-07. Options: have the Claude collector fetch pages (WebFetch) for the 12 big lanes (Iran war, Ukraine, AI releases, markets, Israel/Gaza, China, US politics, cyber, Europe); add a **fixed watchlist of standing stories** (Iran war day count and diplomacy, Venezuela, Greenland/Golden Dome, Poland/NATO eastern flank, data-center moratorium and power, AI model releases) that each collector must search by name every day and report "nothing new" explicitly. This is the cheapest fix for the specific misses you named.
5. **Move the MSI RSS/search capture earlier** (it ran 19:01) or add a morning pass at 8:30, and get working AP/Reuters feeds (all three are "unavailable"). The only evidence of the 10/7 model news was in that late file.
6. **DeepSeek reader hardening:** keep it as a merger but (a) add a post-check in `deepseek_read.py`: count the URLs in the corpus and in the output, and if any URL is missing append it under a `## Unmerged` section, never delete; (b) stop turning "nothing new" lines into `[claim]` items; (c) let the writer read Convergence/Divergence as a "what matters" hint.
7. **Add the previous evening's jaron-x and msi files** to the reader corpus (they are for the day before, so use `day-1`).
8. **Backup writer parity:** the 10-07 MSI backup used only Codex's capture style and a thinner scope; it should use the same prompt and coverage rule as the cloud routine and say in its header which writer ran.

Softening findings are in section 7. Priority order if you only do two things: #1 (coverage rule) and #4 (standing watchlist searched by name).
