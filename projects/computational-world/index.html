The three ways

    
    
      
  1. A plain program. Ordinary code. It looks at the whole pile again after every change.
    2. 
      
  2. The Minecraft way. The same answer built out of tiny logic gates, like a redstone computer. Every gate updates on every tick, whether anything near it changed or not.
    3. 
      
  3. This world's own parts. Parts made for the job: one counter for each set. A change travels only along its own links, and everything else stays quiet.
    4. 
    

    
The first number is not time. It is how many small steps each way had to take for your last tap. A world never beats a plain program doing the same steps on the same chip. What a world can change is how many steps there are.
